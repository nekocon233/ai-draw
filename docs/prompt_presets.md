# 提示词预设选择

预设由 `server/api/prompt.py` 维护，经需要登录的 `GET /api/prompt/presets` 返回，统一通过输入区加号菜单选择。灯泡按钮打开「扩写助手」，只提供文字扩写、结果编辑、复制和应用，不再包含预设、图片分析或动作识别标签页；动作参考的「＋ → 生成提示词」保留。

输入区底部工具栏的“参考图”按钮左侧提供 `PromptPresetQuickSelect` 快捷入口：一个无边框的小加号，普通模式的悬停和无障碍名称为“添加预设”；动作参考模式为“更多操作”，并提供直接将看图结果填入输入框的“生成提示词”。已选预设标签仍在输入框上方显示，未选择时不占用额外一行。标签详情中的“更换预设”也打开同一个加号菜单。每次展开菜单都获取最新列表，显示用途和所需参考图数量；加载失败时支持在菜单中重试。窄屏菜单可沿水平方向移回可视区域，避免仅翻转对齐后仍被裁切。选择“不使用预设”或移除已选标签均会清空选择。

预设菜单通过 `getWorkflowPresets()` 按 `workflow_ids`、`output_type` 和输入能力筛选，仅显示当前生成方式适用的预设，不展示禁用项。旧快照缺少 `output_type` 时视为图片预设，缺少 `workflow_ids` 时沿用原有能力校验。允许先选预设再添加参考图；缺图提示显示在选中标签上，提交和历史消息重新生成均会校验。选中标签可查看完整文案。

选择和清除复用 `setPromptPreset()` 与既有会话保存逻辑。输入框始终只保存用户补充描述，预设内容保存在 `prompt_preset` 快照中；生成时后端再拼接预设与描述。保存的描述不变。读取菜单不会自动更新已保存的快照，用户重新选择才使用服务端最新文案，历史消息保持原有快照。

「扩写助手」按会话、生图 / 生视频分别保存草稿（原始描述和最近一次扩写结果），由 `frontend/src/utils/promptExpansionDrafts.ts` 存在浏览器 localStorage 中，只保留最近 60 份，退出登录时清空；旧版只按会话保存的草稿在两类里都能读到，某一类第一次保存时交给另一类，不会丢失。只有在弹窗里扩写、编辑或手动填入过，才会开始保存；应用结果、关闭弹窗或刷新页面后，草稿都还在。再次打开时，已保存的原始描述不会被输入框内容（通常是已应用的扩写结果）覆盖，需要时点“用输入框内容覆盖”手动替换；当前会话的这一类还没有草稿时，才用输入框内容预填。

「扩写助手」只扩写描述，不扩写预设。如果已选预设适用于当前工作流，前端只把预设原文作为 `preset_prompt` 发给 `POST /api/prompt/generate`；不适用的旧快照不发送。后端把它放进系统上下文交给模型，其中的 `@图片N`／`<imageN>` 改成普通文字“图片N”。模型只扩写用户描述，不复述或改写预设，也不新增与预设冲突的内容，用户描述里的每项要求都保留原意。扩写结果仍只写回描述，生成时后端照常拼接一次预设。选中预设时，弹窗提示“预设「标题」生成时自动添加，不参与扩写”。

生图方式 Qwen-Image-2.1（文字／编辑共用）与 GPT Image 的 `default_prompt_preset_id` 均为 `sketch_finish`，首次进入默认选中「参考图成品化」。预设沿用现有文案，需要一张参考图；无图时显示缺图提示，添加图片后即可只用预设提交，也可填写人物、服装、背景等补充要求。2026-09-27 起，文案明确要求完整上色：参考图是黑白线稿、灰度草图或只上了部分颜色时，也要给皮肤、头发、眼睛、服装和配饰全部上色；颜色以补充描述为准，未指定的部分合理配色，除非另有要求不输出黑白或只有线条的画面。输入框提示改为“补充人物外观、服装配色、背景颜色等具体要求”。已保存的旧快照不变，重新选择一次预设才会用上新文案。新会话的描述为空，不填入示例句子；已有描述和预设快照不改写，手动取消后可以按工作流原本的能力纯文字生成。

Qwen 的文字与编辑执行图共享同一个生图入口。手动更换或取消预设会同时记录到两个工作流键，上传／移除参考图触发自动切换时保持该选择。旧会话仅保存过其中一个键时，另一执行图首次使用会沿用它；两个键都有历史值时先尊重当前键。GPT Image 与视频模式仍各自保存选择，刷新和重新打开预设目录不会覆盖明确的取消。

视频预设包括：

| 预设 | 用途 | 所需输入 |
| --- | --- | --- |
| 自然动作 | 保持主体一致，补充动作、幅度和速度 | 开始帧 |
| 固定镜头动作 | 固定原图人物、场景与镜头，主体按动作参考图依次运动；文字仅补充额外细节 | 原始画面、动作参考图 |
| 参考镜头动作 | 主体图只提供人物或元素外观；镜头、构图、动作姿势和场景跟随参考图，按顺序连续衔接 | 主体图、参考图 |
| 首尾帧过渡 | 补齐两个状态之间的连续动作 | 开始帧、结束帧 |

“自然动作”和“首尾帧过渡”仅在 **MiniMax H3 · 首尾帧**（`minimax_h3`）中显示，默认选中“首尾帧过渡”。**MiniMax H3 · 动作参考**（`minimax_h3_ref`）显示“固定镜头动作”和“参考镜头动作”，默认选中“固定镜头动作”；基本动作、目标姿态和顺序均以图片为准，补充文字仅提供节奏、停顿、音效等额外内容，可留空，不能替换或颠倒参考动作。Wan 工作流已停用，历史记录和预设快照仍保留，但不能直接重生成；旧会话回退到当前可用方式。

两个 H3 的 `default_prompt_preset_id` 配置在工作流元数据中，完整文案仍从认证后的预设接口加载。首次进入模式自动选中默认预设，输入框只保存补充内容。首尾帧过渡仍需首尾两张图，固定镜头动作仍需原图与动作图；选择“不使用预设”后沿用工作流本身的输入能力。

会话的 nullable JSON 列 `config_prompt_preset_choices` 按工作流保存预设快照：缺少键表示尚未初始化，值为 `null` 表示手动取消。启动以幂等 DDL 增加该列，旧会话有预设则保留原快照，无预设时首次补齐该模式默认项。手动切换或取消后，刷新、模式往返与再次打开菜单均恢复选择。当前 `prompt_preset` 继续用于显示和生成，消息仍只保存当轮快照；延迟到达的预设列表不能覆盖手动选择，会话配置加载期间不会应用默认项。

`PromptPresetImage.slot` 指定输入位置：`1`/`2`/`3` 为普通参考图，`end` 为独立的结束帧；缺省沿用图片列表顺序。第二张普通参考图不能代替结束帧。后端 `WorkflowCatalog` 在拼接前校验预设类型和必填位置，因此绕过前端也不能跨类型或缺图提交。视频预设使用“本段起始/结束帧”表达，不包含图像模型专用的 `@图片` 标记。

`PromptPreset.requires_motion_reference` 默认为 `false`；固定镜头动作新预设为 `true`，前后端同时校验工作流的 `supports_motion_reference` 能力和独立的 `motion_reference_images`。旧快照没有该标志，仍按原始工作流与文案使用；重新选择预设才启用新规则。Ref2VA 的视觉分析与最终提示词始终遵循图片动作优先，分析策略标识加入输入指纹后，旧分析缓存会自动失效。

`PromptPreset.motion_reference_mode` 决定动作参考中两类图片的作用，缺省为 `pose`，旧快照也按 `pose` 处理：
- `pose`（固定镜头动作）：主体图提供人物、场景和固定镜头，参考图只提供姿势。
- `shot`（参考镜头动作）：主体图只提供人物或元素的外观，镜头、构图、动作姿势和场景都跟随参考图。

生成时 `GenerationParameters.for_provider()` 把这个字段转成 provider 可见的 `motion_reference_mode`，该值不单独保存，由预设快照推出。选了参考镜头动作后，前端的动作图区域和缺图提示改用“参考图”“主体图”等说法。详见 [MiniMax H3 动作参考](minimax_h3_reference.md#参考镜头动作)。
