# MiniMax H3 动作参考视频

在“图生视频”的生成方式中选择 **MiniMax H3 · 动作参考**。上传原始角色与场景图，再添加 1–8 张按动作顺序排列的姿势图；支持多选、粘贴、拖入和现有 posemy.art 截图。箭头调整动作顺序，补充文字可留空，也可写节奏、停顿和必要音效等额外内容。基本动作、目标姿态和顺序由参考图决定，无需手动重复描述；文字与参考动作冲突时以图片为准。系统在生成视频前自动看图识别动作。

该模式直接使用 H3-Base-Ref2VA；不先重绘角色关键帧。角色图作为 `<Picture 1>`，动作图依次为 `<Picture 2>` 到 `<Picture 9>`。服务端自动描述各图的角色：外观与画风来自角色图，白模仅提供姿态、身体朝向和动作顺序。原图通过 `MiniMaxH3ReferenceToVideo` 的参考输入进入模型，不接首尾帧或 Add Guide。它是语义动作参考，姿态、时间点及角色一致性仍需实际检查。

输出沿用 H3：24 FPS、原生双声道音频、约 4–15 秒；帧数按 `17k+5` 向上对齐，因此成片时长可能略长。画幅固定跟随原图（按模型尺寸网格对齐），历史记录的其它画幅选项也按原图处理，避免改动取景。动作参考图可使用不同的宽高比。参考图尺寸使用 `match`，避免不必要地放大参考图 token 数。

## 自动动作提示词

- 第一张图是人物、场景、光照、画风、镜头、构图和裁切的唯一基准。固定要求始终由服务端拼接，不允许自动扩写或手工动作文字引入运镜、变焦、换背景、拉远补全画外身体、额外人物或特效；仅转移动作图中的身体姿态。生成模型仍可能出现偏差，不能保证背景逐像素不动。
- 视觉分析同时读取原图与全部有序动作图，分别识别姿态和连续衔接；区分人物自身左右与画面左右，避免猜测遮挡细节。复用现有 `LanguageModel` 的 Codex 视觉连接，不增加模型部署或环境配置。
- 生成任务先进入可取消的分析阶段，失败时不启动 ComfyUI，保留旧结果。`ProviderRegistration.enrich` / `GenerationEngine.prepare` 在既有单任务生命周期内补齐分析，HTTP 路由不执行后台生成业务。
- 输入区通过“＋ → 生成提示词”直接将看图结果填入对话输入框，作为可编辑的提交草稿；同时将分析快照绑定到填入后的文字，避免随后生成视频时重复分析。未使用这一手动操作时，自动分析仍与原始补充描述分开保存。切换图片、顺序、要求或会话后，旧请求会取消或丢弃，不能覆盖新输入。“固定镜头动作”预设要求原图和动作图，明确动作以参考图为准，手动描述只提供额外细节。
- 「扩写助手」在此模式只扩写补充描述。固定画面要求和按参考图顺序完成的基本动作由服务端拼接，不再写进扩写结果，“固定镜头动作”预设也只作只读上下文。描述里已有的内容（包括填入的看图结果）保持原意和顺序；随动作产生的头发、衣物细微动态可以扩写，但不得新增或改变参考动作。
- `POST /api/prompt/analyze-motion` 接收 `reference_image`、`motion_reference_images` 和可为空的 `description`，返回版本、`input_hash` 和 `prompt`。接口认证并检查本地引用归属，再规范化图片；不抓取站外图片 URL。
- `motion_prompt` 快照存入会话 `config_motion_prompt` 和消息 `motion_prompt` 的 nullable JSON 列，通过启动时幂等 DDL 添加。输入指纹涵盖原图、动作顺序、有效补充描述（含所选预设）、模板版本及分析策略标识。匹配时保留人工修改并复用，过期或缺失时重新分析；旧策略的缓存会自动失效。历史重生成使用当轮快照，旧记录自动补充分析。

## 模型

新增 `minimax_h3_ref2va_pruned_int8_convrot.safetensors`，复用已安装的 H3 Qwen3-VL-32B 编码器和视频／音频 VAE。ComfyUI 必须有 `MiniMaxH3ReferenceToVideo`。权重来自 [Comfy-Org/MiniMax-H3](https://huggingface.co/Comfy-Org/MiniMax-H3)，大小 20,970,379,616 字节，SHA-256 为 `9255f52b6677845ad238f20dfaafa94727053694127ab7f255c048f0f9365779`。

安装到现有 ComfyUI 模型目录：

```bash
python3 -B scripts/install_minimax_h3_ref.py /path/to/ComfyUI/models/diffusion_models
```

安装脚本支持分段下载和续传，校验完整文件后才启用正式文件名，不覆盖已有的不匹配权重。

## 数据与执行

- 工作流 `minimax_h3_ref`，provider `comfyui_minimax_h3_ref`，API 模板 `minimax_h3_ref_workflow_api.json`。
- `reference_image` 保存角色图，新增 `motion_reference_images` 保存有序动作图；不用旧的第二、第三参考图或尾帧字段承载动作列表。
- 会话 `config_motion_reference_images`、消息 `motion_reference_images` 使用 nullable JSON 列，通过启动时 `ADD COLUMN IF NOT EXISTS` 迁移。旧记录为空；刷新、历史显示和编辑重生成保留顺序，重生成不读取当前输入栏的动作图。
- 沿用单任务生命周期、用户隔离、取消、结果落库与媒体清理；新输入同样验证引用归属，仍被会话或消息引用的动作图不会被清理。
- 动作分析走现有 Codex 视觉连接，视频生成由本地 ComfyUI Ref2VA 执行。
